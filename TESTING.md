# Перевірка Nodi 1.0.0-alpha.3

Це наступна версія розробки, не підтвердження публікації релізу.
Схема версій наведена в README: Android 1.0.0-alpha.3 / code 3,
macOS 1.0.0 / build 6, мінімальна версія Go — 1.22.

## Статус цієї перевірки — 2026-10-30

Переглянуто код і наявні тести з NODI-current.zip. Перевірено узгодженість
метаданих версій, XML/plist та синтаксис скрипта оновлення.
У середовищі підготовки немає Go, Android SDK і macOS/AppKit, тому Go-тести,
Android-збірку й Swift-компіляцію тут НЕ запускали. Старі результати Go 1.23.2
не вважаються перевіркою цього знімка. Локальний інсталятор етапу 0 запускає
перевірки Go перед комітами; їхній результат видно в терміналі користувача.

Раніше користувач підтвердив на Samsung приймання після перезапуску без повторного
вибору папки. Це окремий перевірений сценарій попереднього оновлення, а не повна
регресійна перевірка актуальної збірки. Останні зміни Open/Share та інтерфейсу
потребують повторної перевірки на пристроях.

## Відтворювані перевірки

З кореня репозиторію:

```bash
go version
go vet ./...
go test -race ./...
python3 scripts/check-core.py
bash -n scripts/run-macos.sh
```

Для race потрібен компілятор C і підтримуване середовище. Записуйте версію Go,
ОС, commit hash і фактичний результат; відсутність інструментів не означає успіх.
На Mac додатково: `bash scripts/run-macos.sh`; для APK:
`cd android && bash ./gradlew assembleDebug` із налаштованими JAVA_HOME та Android SDK.
Скрипт Mac прив'язаний до SDK MacOSX26.5; перевірити шлях перед збіркою.

## Що покривають наявні автоматичні тести

- `transfer_test.go`: порожній/UTF-8/бінарний файл 1 MiB, неправильний токен
  і TLS-відбиток, збереження наявного файлу й symlink, небезпечні імена,
  завеликий розмір/заголовок, неправильний SHA-256, обрив, некоректні invite-коди.
- `wifi_test.go`: взаємне підтвердження, відкритий режим discovery, відмова
  будь-якого боку, відсутність/зміна/прострочення вибору, змінений commitment,
  прив'язка коду порівняння до даних обміну, незмінність QR bootstrap при Wi-Fi pairing.
- `wifi_request_test.go`: TLS pin запиту з'єднання, відмова при невірному pin,
  склад запиту без токена/секрету та кілька невалідних аргументів.
- `scripts/check-core.py`: два CLI-процеси, передача 1 MiB, UTF-8 ім'я,
  побайтовий збіг, JSON-події, код через stdin, відмова при перезаписі,
  неправильний код, SIGTERM і очищення часткового файла.

Ці тести не є перевіркою Kotlin ↔ Go, mDNS у реальній мережі чи нативного UI.
Перевірка незмінності bootstrap не замінює повний тест QR-парингу.

## Ручна регресія Mac ↔ Android

1. Чистий перший запуск: мова/назва, відсутність вигаданих збережених пар.
   На Android без папки пошук, QR і надсилання не повинні відкривати вибір папки.
2. Wi-Fi: знайти пристрій; почати підключення спочатку з Mac, потім з Android.
   На іншому екрані має з'явитися запит без ручного вибору зі списку.
   Звірити код, підтвердити й перевірити повідомлення «З'єднано» та збережену пару.
3. Відхилення, різні коди, тайм-аут, одночасні запити: не створювати довірену пару.
   Повторити підключення після відмови; QR має працювати незалежно від Wi-Fi способу.
4. Папка Android: вибрати, дозволити доступ, прийняти файл. Закрити/відкрити Nodi,
   потім перезавантажити телефон і повторити без повторного вибору папки.
   Окремо відкликати доступ: зрозуміла помилка й можливість вибрати папку знову.
5. Приймання вимкнене: файл не записується, підключення залишається доступним.
   На Mac змінити папку при ввімкненому приймачі й перевірити новий шлях.
6. Обидва напрямки: кілька файлів, порожній файл, довгі/Unicode імена;
   скасувати вибір до відправки й активну передачу. Перевірити відсутність залишків.
7. Android: прев'ю зображення, Open і Share для фото/PDF/невідомого типу;
   відсутність відповідного застосунку не спричиняє падіння.
8. Повторне ім'я не перезаписує файл. Видалення пари й повторний пошук/паринг.
9. Зміна Wi-Fi, зникнення мережі, фоновий режим/блокування екрана,
   зупинка сервісу, завершення програми під час передачі.
10. Три вкладки Android, темна/світла тема, довгі назви й анімація «З'єднано».

## Відомі прогалини

- Немає окремого повного набору DeviceBook-тестів: збереження/повторне відкриття
  identity, devices.lock, пошкоджені файли, одноразовість/строк QR, дублікати,
  ліміт пристроїв, Authorize, Forget/Unlink та гонка Forget проти Commit.
- Немає збереженого автоматичного end-to-end тесту Kotlin ↔ Go або UI-регресії.
  Android ExampleUnitTest/ExampleInstrumentedTest — шаблонні тести, не покриття Nodi.
- Немає підтвердження для цього знімка: Go 1.22, повний диск, 2 GiB,
  дві одночасні вхідні передачі, різні document providers, різні моделі Android,
  мережі з client isolation/multicast filtering, незалежний аудит безпеки.
- Підпис/нотаризація macOS та release-підпис Android не перевірені цим етапом.
