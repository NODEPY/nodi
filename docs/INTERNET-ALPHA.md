# Nodi: кімнати через інтернет

1. На першому пристрої натисни **Інтернет → Створити кімнату**.
2. Передай код іншій людині приватно.
3. На другому пристрої: **Інтернет → введи код → Приєднатися**.
4. Власник кімнати звіряє код і підтверджує очікуваний пристрій.
5. Увімкни приймання на обох пристроях, вибери папку, якщо її ще не вибрано.
   Вибери підключений пристрій і надсилай файли або текст.

IP-адреси, VPN, попереднє спарення в одній мережі та операторські коди активації
не потрібні. Кімната потрібна лише для першого підключення: спарені пристрої
зберігаються. Код складається з 16 символів і діє п’ять хвилин. Повторне натискання
**Інтернет** під час очікування дозволяє скасувати кімнату.

Код кімнати — секрет: він шифрує дані спарення. Сервер не бачить токен передачі.
Передача файлів і тексту додатково використовує наявний TLS із перевіркою
сертифіката спареного пристрою. Якщо пряме TCP-з’єднання недоступне, клієнт
автоматично використовує Cloudflare. Помилка TLS не запускає повторне надсилання.

## Збірки

- Для власних тестів автора: `build/nodi-android-rooms-test.apk` та
  `build/nodi-macos-rooms-test.zip` (також `build/Nodi.app`).
- Для інших користувачів: `build/nodi-android-rooms.apk` та
  `build/nodi-macos-rooms.zip`.

Обидва варіанти збирає `bash scripts/build-rooms.sh`. Він явно передає
`-PnodiTestInstall=true/false` для Android і `NODI_TEST_INSTALL=true/false`
для macOS, тому тестова збірка не може випадково стати публічною. Тестовий APK
має `BuildConfig.NODI_TEST_INSTALL=true`, публічний — `false`; у Mac це поле
`NodiTestInstall` в `Info.plist`. Обидва APK підписані тим самим Android Debug
ключем, тому встановлюються поверх попереднього.

У цьому середовищі `xcrun` за замовчуванням вибирає MacOSX27.0.sdk, несумісний
зі Swift 6.3.3. Якщо `SDKROOT` не задано, `scripts/build-rooms.sh` сам вибирає
`/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk`, коли той існує; інакше
попереджає й використовує стандартний SDK. Ручне задання `SDKROOT` лишається
способом перевизначити SDK:

```sh
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk bash scripts/build-rooms.sh
```

Встановлюй APK поверх попереднього з тим самим підписом, щоб зберегти спарення.
Не видаляй дані застосунку: це змінить ідентичність пристрою. Це debug APK і
локально підписані Mac-збірки, без нотаризації; версії не змінено, GitHub-реліз
не створено. Старі файли `*-internet.*` стосуються попередньої збірки.

## Відгуки й приватність

Кнопка **Відгук / приватність** на Android і **Відгук** на Mac надсилає текст автору.
Не вставляй у відгук паролі чи вміст приватних файлів. На Mac спочатку потрібне
ввімкнення Інтернету через створення або приєднання до кімнати.

Статистика добровільна й вимкнена за замовчуванням. За згодою враховуються
активні встановлення та кількість успішних надсилань файлів/тексту. Імена файлів,
вміст повідомлень, контакти й особисті імена не надсилаються. Сервер прив’язує
добові записи до ідентичності встановлення — це псевдонімні, не анонімні дані.
Приватний звіт не розкриває ідентифікатори; записи видаляються через 30 днів.

Особисті тестові збірки не надсилають статистику навіть після перевстановлення.
Наявні Mac і S21 FE автора також виключені на сервері. Якщо після видалення даних
встановити звичайну публічну збірку й дати згоду на статистику, це буде нове
встановлення: Nodi не відстежує апаратний ідентифікатор телефона.

## Приватний звіт автора

Запусти з кореня репозиторію:

```sh
node scripts/internet-report.mjs
```

Відкрий `build/private-report/index.html`. Доступ до API звіту захищений окремим
адміністративним ключем; ключ не входить у застосунки чи HTML. Файл звіту має
права 0600, папка — 0700. Це локальний знімок: команда оновлює його.

Облік переходів до завантаження реалізовано окремо. Він почне працювати після
налаштування адрес опублікованих APK/ZIP у Worker. Зараз нові збірки ще не
опубліковані в GitHub-релізі. Запити за посиланням не дорівнюють завершеним
завантаженням чи кількості людей. Прямі завантаження з GitHub цей лічильник
не бачить. Для тестів автора передбачені окремі посилання без підрахунку.

## Межі альфи

Через інтернет — до 16 MiB на файл, сесія до 10 хвилин, приймання має залишатися
увімкненим. Опитування сервера може додавати до 10 секунд затримки. Сервер поки
обмежений 64 зареєстрованими ідентичностями та 16 одночасними передачами.

## Ручний тест на фізичних пристроях

Автоматичні Miniflare, Go, Android та Kotlin/Go interop тести пройшли, але вони
не перевіряють AndroidKeyStore, Keychain, UI, дозволи macOS і реальні мережі.
Нижче — обов’язковий ручний прогін. Позначай результат у таблиці в кінці.

Підготовка:

1. Встанови тестові збірки поверх наявних, не видаляючи дані застосунків.
2. Mac підключи до Wi-Fi, Android — до мобільних даних; VPN і ручні адреси вимкни.
3. Увімкни приймання на обох пристроях і вибери папку на кожному.
4. Коди кімнат передавай лише приватно; не публікуй їх і не додавай у звіти.

Сценарії:

1. **Mac створює кімнату, Android приєднується.** На Mac: **Інтернет → Створити
   кімнату**. На Android введи код → **Приєднатися**. На Mac звір код і натисни
   **Підключити** лише для очікуваного пристрою. Очікування: обидва показують
   підключення, зайвий пристрій не з’являється.
2. **Файл і текст Mac → Android.** Надішли файл (менше 16 MiB) і текст. Перевір
   ім’я, розмір і SHA-256 файлу та точний текст на Android.
3. **Файл і текст Android → Mac.** Повтори у зворотному напрямку; перевір
   байт-у-байт і Unicode.
4. **Android створює кімнату, Mac приєднується.** Повтори підтвердження й обмін
   в обидва боки. Це перевіряє обидві ролі, а не лише Mac-host.
5. **Перезапуск.** Закрий обидва застосунки, запусти знову, увімкни приймання.
   Спарені пристрої та інтернет-доступ мають зберегтися; новий обмін має йти без
   створення кімнати. Якщо кімната вже була використана, повторно той самий код
   не приймається.
6. **Скасування.** Створи кімнату, приєднайся з другого пристрою, але до
   підтвердження натисни **Інтернет → Скасувати кімнату** (або закрий очікування).
   Очікування: обидві сторони отримують зрозумілу відмову; код більше не діє.
7. **Неправильний код.** Зміни один символ коду. Очікування: помилка, нового
   спарення немає, статистика не змінюється.
8. **Прострочений код.** Створи кімнату й зачекай понад 5 хвилин, не підтверджуючи.
   Очікування: код відхиляється, кімната зникає, повторне використання неможливе.
9. **Статистика тестової збірки.** На `-test` збірці увімкни статистику, надішли
   файл/текст, залиш відгук. Онови `build/private-report/index.html`. Очікування:
   нових записів немає, відгук не з’являється.
10. **Статистика публічної збірки.** На звичайній збірці без згоди нічого не
    надсилай; перевір, що звіт не змінився. Потім дай згоду, надішли файл/текст і
    залиш відгук; онови звіт. Очікування: з’являються лише псевдонімні денні
    лічильники та текст відгуку, без імен файлів, контенту, контактів чи IP.

Не зараховуй як успіх запуск, що впав до встановлення транспорту (наприклад,
`NoRouteToHost` або відсутній дозвіл macOS). Для кожного сценарію перевір, що
помилка сталася на очікуваному кроці, а не через мережу чи UI.
