# Nodi — перша передача файлу

Консольний режим ядра на Go. Надсилає один файл напряму через
зашифроване TCP-з'єднання. Ці команди працюють через термінал; віконний застосунок
для Mac описаний у головному README.md. Android-застосунок описаний у головному README.md. Немає хмарного сховища, облікових записів чи сторонніх
Go-залежностей.

## 1. Підготовка

Потрібен Go 1.22 або новіший. Для реального використання встанови актуальну
підтримувану версію з https://go.dev/dl/ . На Mac з чипом Apple обери macOS ARM64.

Розпакуй архів. У папці проєкту мають бути `go.mod`, `cmd`, `internal` і цей README.
Відкрий термінал у цій папці та перевір:

```sh
go version
go test ./...
```

## 2. Перший тест на одному комп'ютері

У першому терміналі, з папки проєкту:

```sh
go run ./cmd/nodi receive -listen 127.0.0.1:7331
```

Залиш його відкритим. Скопіюй ВЕСЬ рядок, що починається з `nodi1-`.
Відкрий другий термінал у тій самій папці та надішли файл проєкту:

```sh
go run ./cmd/nodi send -code 'ВСТАВ_КОД_СЮДИ' -file README.md
```

Після повідомлення `Sent. Receiver verified and saved the file.` перевір:

```sh
cmp README.md received/README.md
```

Якщо `cmp` нічого не вивів — файли однакові. Повторне надсилання цього ж імені
буде відхилене: Nodi не перезаписує вже отримані файли.

## 3. Два комп'ютери в одній мережі

На комп'ютері-одержувачі:

```sh
go run ./cmd/nodi receive
```

Цей режим слухає всі мережеві інтерфейси. Дозволь вхідне з'єднання у системному
фаєрволі, якщо macOS запитає. Обери код під адресою локального Wi-Fi / Ethernet,
наприклад `192.168.1.12:7331`, а не під `127.0.0.1`. VPN може додати зайві адреси.

На іншому комп'ютері з Go та цим проєктом:

```sh
go run ./cmd/nodi send -code 'КОД_ОДЕРЖУВАЧА' -file '/повний/шлях/до/файлу'
```

Для зворотної передачі поміняй ролі: запусти `receive` на іншому пристрої.
Мережі з ізоляцією Wi-Fi-клієнтів можуть блокувати з'єднання.
Через різні інтернет-мережі цей прототип не налаштовує з'єднання автоматично.

Додаткові параметри:

```sh
go run ./cmd/nodi receive -out ./received -listen 0.0.0.0:7331 -max-mib 2048
go build -o bin/nodi ./cmd/nodi
```

## Як влаштований код

- `cmd/nodi/main.go` — команди `receive` і `send`, адреси, папка отримання.
- `internal/transfer/transfer.go` — TLS, код з'єднання, передача й SHA-256.
- `internal/transfer/transfer_test.go` — інтеграційні тести та помилкові передачі.

Одержувач створює тимчасовий TLS-сертифікат і випадковий 256-бітний токен.
Код містить адресу, токен і SHA-256 відбиток сертифіката. Відправник перевіряє
цей відбиток перед передачею. Заголовок містить ім'я, розмір, токен та SHA-256 файлу.
Після дозволу йдуть байти, після перевірки й збереження — остаточне підтвердження.
Файли передаються потоково; відправник спочатку читає файл для обчислення хешу.

## Межі цієї версії

- Код секретний: будь-хто з ним може надсилати файли до зупинки одержувача.
  Передавай його довіреним каналом. Він не одноразовий; перезапуск змінює код.
  Поки що немає окремого підтвердження кожного відправника.
- За замовчуванням максимум 2 GiB на файл та дві одночасні передачі. Загальна
  дискова квота не реалізована: перевір вільне місце й зупини прийом після тесту.
- Граничний час однієї передачі — 30 хвилин. Немає відновлення після обриву,
  відсотка прогресу, передачі папок, перегляду віддалених файлів чи QR.
- Ctrl+C зупиняє процес. При звичайному обриві тимчасовий файл видаляється;
  при примусовому завершенні / вимкненні може лишитися прихований `.nodi-*.part`.
- Використовуй окрему локальну папку отримання, доступну лише тобі. Фіналізація
  потребує hard links (підходять APFS/ext4; FAT/exFAT не підходять).
- Якщо з'єднання обірвалося після збереження, але до підтвердження, файл уже
  може бути в одержувача. Перед повтором перевір його папку.
- Це прототип для тестування на своїх пристроях, не завершений публічний продукт.

Наступні етапи: явне підтвердження вхідної передачі, прогрес,
зв'язування пристроїв і QR.
